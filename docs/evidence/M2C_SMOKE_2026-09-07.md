## Model behaviors (not Keel defects)

1. **Shell operators inside `argv`.** For "create a file containing hello" the
   model sent `["echo","hello",">","keel_smoke.txt"]` three times (and once
   with `printf`). Keel runs argv without a shell, so `>` was an argument:
   `echo` printed `hello > keel_smoke.txt`, exit 0, no file. The model
   recognized "the prior shell commands did not create it" in turn 7 and
   repeated the same form in turn 8. It never requested a shell
   (`["powershell","-Command",…]` or `["bash","-lc",…]`), although it used
   `powershell -Command` for probe 2.
2. **No `Safety:` review in full mode.** PIRA requires a `Safety:` review
   before state-changing commands when no host approval exists. The model
   attempted six writes and one delete without printing one, although in the
   M2 B run it had correctly described this very rule.
3. Mixed platform vocabulary: cmd built-ins (`type`, `dir`) as programs
   (exit 127), PowerShell, and Git Bash tools in one session.
4. Probe 5 deleted a file that never existed (`rm -f`, exit 0) and reported
   "Done" without verifying; probe 6's `dir` would also have failed as a
   built-in had it been approved.
5. The ask-mode refusal explanation mixed the command's read-only nature into
   the reason it did not run.

## Decisions taken on this evidence

- **Reject standalone shell operators in `argv`.** Keel still interprets no
  shell syntax (O3). But `>`, `|`, `&&`, `;`, and similar as their own
  `argv` elements are never a program argument the model means; treating
  them as a validation error with an actionable message turns a silent
  misfire (exit 0, nothing happened) into a first-turn correction. The
  message names the platform's shell forms. A legitimate literal operator
  argument can still be passed through an explicit shell.
- **Platform-aware tool description.** The `shell` spec now says which shell
  forms exist on this platform and that cmd built-ins are not programs.
- **`max_turns` raised from 8 to 32.** Eight was chosen for M0 tests. A real
  multi-step task with a couple of retries exceeds it; 32 keeps the fuse
  meaningful without cutting off ordinary work.
- **`Safety:` in full mode stays a PIRA rule, not a Keel check** (O5,
  confirmed by the user on this evidence). This run shows that PIRA's
  semantic safety is not a runtime-enforced guarantee for this model. It does
  not show that Keel should classify command semantics itself: a risk
  classifier would be a hard-to-get-right subsystem that looks like
  enforcement without being reliable. Decision: retain model-owned semantic
  safety in `full` mode; `ask` remains the default and the recommended mode
  when model compliance has not been demonstrated; do not add a command-risk
  classifier from one-model evidence; revisit after broader model evidence or
  a concrete failure that `ask` cannot acceptably control. The `--full` help
  text and the host block state this boundary plainly.

## Limits of this evidence

One model, one run per mode. The operator-in-argv habit may be specific to
this model; the missing `Safety:` review is one data point about this model
and this run, not about local models in general. Both are worth re-testing
after the changes above, and the same probes on other models are what would
build model-side evidence.
