## Why the pointer could not work

The pointer addressed "the model cannot find the rule". Qwen showed the model
finding the rule, judging it applicable, and planning the review, then
emitting only a tool call. A cue that improves retrieval has nothing to act on
when retrieval already succeeded.

## Why this is a harness matter, and what it is not

Two independent local models we intend to run both drop a required
pre-action step when it lives only in assistant prose. Tool-oriented models
in a full agent context tend naturally toward `content = null, tool_calls =
[…]`; a harness that requires a critical state to appear in the free-text
channel is relying on something those models routinely omit.

This is not:

- a PIRA policy defect: PIRA correctly specifies when a review is needed and
  what it must consider;
- a Keel implementation bug: the code does what the design said;
- a model compatibility limitation only: two models, same behavior, with
  reasoning evidence that the rule was understood.

It is: **Keel's integration architecture for PIRA's safety requirement is too
weak. An execution-order invariant is implemented as a prompt-only
behavioral expectation.**

## The ownership split that follows

```text
semantic safety review                          → PIRA / model
  (is this state-changing? action, scope, risk, rollback)

pre-execution safety-review protocol            → Keel
  (a review artifact must precede execution of a
   state-changing action; Keel emits it visibly, then executes)
```

Keel still does not judge whether `cargo test` or `python script.py` changes
state. It only guarantees that once the model says an action is
state-changing, the review step cannot be skipped. No RiskClassifier.

## What is deprioritized

- Response Style ablation: still of research interest, no longer of
  engineering value. Whichever sentence interacts with the rule, the fact
  stands that our intended models may drop the pre-action review.
- A third model as a gate: useful, not necessary. Two independent models
  with reasoning evidence justify designing a minimal mechanism and testing
  it.

## Next step

Design and run a minimal **structured pre-execution safety handshake**
experiment (`docs/T15_HANDSHAKE_AB.md`) on the same Qwen and Mistral
configurations, without changing production code. If it restores compliance
from 0/5 to stable compliance, the mechanism enters Keel; if not, the design
is revisited before anything ships.
