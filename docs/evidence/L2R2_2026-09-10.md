## Dominant failure, classified

**Terminal failure: model-call budget exhausted at 100 with the task
incomplete.** This is the first run in which the explicit budget was the
binding limit. Keel behaved as designed: the banner announced the budget,
`run_end` carries `turns: 100` and the error, the transcript is kept, no
continuation or retry happened, and `session_stats.py` reports it as one
failed run with 100 calls. T22's implementation conclusion stands; its
task-level conclusion sharpens: **100 calls were not sufficient for this
task in this run**, while L2 completed in 76 calls with two continuations.
Per the fixed rule, N is not raised on this evidence.

**Where the calls went** (from the counts; call-by-call attribution awaits
the `log show` line count and the full diff, neither of which changes the
classification): 94 of 123 tool calls were shell, 34 tool results were
errors, and the error list shows repair loops on the model's own artifacts:
six zero-match `edit_file` attempts on `tests/test_cli.py` and on a helper
`tests/_check.py` (the latter with CRLF, the exact-match tool's known
Windows friction), runs of `Captured … (exit 1)` and `[stderr]` from
13:57 to 14:01, and three helper scripts plus a captured output left in the
tree. The one failing project test is the model's own column-width
expectation disagreeing with its own implementation; A13 (README) was never
reached, as in L2-R1. The model-side classification is therefore
**call-inefficient self-repair on the `--status` table formatting and on
Windows shell/file mechanics, exhausting the budget before the README**.
This is a model-and-task observation under this configuration, not a Keel
defect, and not a reason to add tools or hints.

**Not observed:** the audited empty-response signature (0/100); any
handshake or ordering violation (0); any outside-workspace attempt (0); any
provider error (0). The single `argv`-collapse denial and the two
review-less edits were each corrected on the next call.

**Two attempts under this protocol, two different terminal failures.**

L2-R2: budget exhaustion at call 100 with 11/13. Neither result overrides
