## Observations by category

Attribution harness-first, as in L1.

1. **Shell editing: not attempted.** With `edit_file` available the model
   made no attempt to write a file through `shell`. The L1 dominant failure
   did not recur. This is the single-variable result the rerun was for.
2. **`edit_file` behavior.** 10/11 edits applied exactly; the one zero-match
   error was the model's own transcription slip, reported by Keel without
   guessing, and repaired by the model in one step after re-reading the
   file. No multi-match occurred. `old_text` sizes ranged from 159 to 1,433
   bytes; the largest replaced the whole `cli.py` body minus its docstring
   line in one edit.
3. **Malformed calls (2, harness-first reading).** Both were `python -m
   pira_ctx …` without `intent`: the model tried to perform the `pira_ctx`
   wrapping itself. The tool description says "Every command runs through
   pira_ctx with your intent", which describes a mechanism the model does
   not operate; the sentence may invite exactly this. Had `intent` been
   present, Keel would have wrapped the call again (`argv[0]` is `python`,
   not a PIRA tool). Recorded as an instruction-path observation; no change
   made in this cycle.
4. **Output truncation on test runs (PIRA tool behavior, not a Keel
   defect).** Three `unittest -v` runs came back through `pira_ctx` in
   automatic mode with `unselected=3808 B/73 lines`, so the model could not
   see the failure details; it re-ran with `2>&1` twice (same result), then
   located the assertion mismatch with `python -c` probes. The retained
   result ids were available to `pira_ctx search`/`range`, and `mode:
   exact` or `capture` was available on the tool; the model used neither.
   Forensic friction, recorded.
5. **cmd escaping (model).** Two `cmd /C "python -c \"…\""` probes failed
   on quoting; the model switched to direct argv within three steps. Same
   root as L1's quoting trouble, now confined to read-only probes.
6. **Unrequested test deletion (model).** See the flagged item under the
   diff. The task said "add tests for both changes"; removing an existing
   test was not asked for and the hidden acceptance does not detect it.
7. **Approval load (harness).** 38 prompts in 3.7 minutes, again answered
   by a driver, not a person. The `edit_file` prompts show sizes rather
   than bodies as designed; the rate problem from L1 stands unchanged and
   was not this rerun's variable.
8. **Empty final turn / T19.** Did not occur: the one run ended with a
   declared completion. T19 remains deferred as decided.
9. **Memory, context.** `pira_ctx` recorded all 27 executed commands with
   legible intents; no memory tool was used or needed. Prompt grew 6.3k →
   23.7k tokens with no sign of forgetting; the single mismatch was a
   transcription error, not context drift.

## What L1-R1 establishes and does not

- Establishes: on this workload and model, registering `edit_file` turned
  a 0/7 run with 28 failed write attempts into a 7/7 run with 10 successful
  edits, no shell writes, fewer calls, fewer tokens, and a quarter of the
  wall clock, with every other variable held.
- Does not establish: behavior on larger or non-Python repositories, on
  files with CRLF endings or non-ASCII content, on multi-match situations,
  or with a human answering prompts at this rate. One run, one model.
